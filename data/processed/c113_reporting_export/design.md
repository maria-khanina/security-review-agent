# reporting export

so this is the thing that makes the finance reports, i think the cleanest way to explain it is to just walk through a night. at 2am the scheduler wakes up the export-job (some people say the exporter, same thing) and the job asks the reporting read replica for the settlements and transactions it needs for the report types finance has asked for, i believe there are six types at the moment but that list lives in the finance wiki so check there, and if the date range is big it chops it into pieces so the replica doesnt get blocked, and then it writes a csv for each report type and range into the exports bucket under a temporary name and renames it at the end so analysts never open a half written file, and if a run fails it writes nothing and shouts in the finance engineering channel, and if you rerun with the same run id it just replaces the file which is nice, and all of this lives in terraform where we have export_key, exports_bucket, reporting_ro_db, reporting_sg, export_audit and export_job_policy, and the whole thing sits in the reporting private subnet i guess, though thats more of a platform thing, and finance analysts download the finished files from the bucket (TBD whether they should get a link in an email instead, finance prefers the bucket for now).

for the security side the platform team gave me a list so im just going to paste what applies and say it in my own words after. Back-office and administrative accounts cannot log in with a password alone, because MFA is enforced. Internal users receive only the roles required for their job, and roles are defined per service. Administrative and debug endpoints are not reachable from the public internet. Every three months the system owners review who has access to production and remove what is no longer needed. and for data it says All personally identifiable information is encrypted before it lands on disk, using AES-256. and also The approved algorithm list is followed, and MD5, SHA-1, DES, 3DES and ECB mode are prohibited in this service. plus Secrets stay out of the repository: not in code, configuration, specs or infrastructure files. and on the network The database and the message brokers sit in private subnets and are not publicly reachable. The exports bucket blocks public access and is private by default. then logging, We log failed logins, changes of privileges and reads of sensitive data. and for personal data Only the personal data needed for the purpose is collected and stored. Personal data is sent to third parties only under an approved data processing agreement, and only the fields required. and for exports specifically Data exports require authorization, are encrypted, and expire after a limited time. finally All queries use bound parameters instead of string concatenation.

what else, the month end run is the heavy one, around forty minutes, it starts at 1am instead of 2am so analysts have the files by nine, the replica is sized for it and the bucket grows by a few gigabytes a month, the heartbeat is checked by finance engineering each morning but the weekend alert routing is still nobody's job (TBD, probably operations), and one more thing, file size, finance wants one file per run and engineering would split above a million rows because excel struggles, still open, i keep meaning to write it down properly and never do.
