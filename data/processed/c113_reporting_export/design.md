# reporting export

so this is the thing that makes the finance reports, i think the cleanest way to explain it is to just walk through a night. at 2am the scheduler wakes up the export-job (some people say the exporter, same thing) and the job asks the reporting read replica for the settlements and transactions it needs for the report types finance has asked for, i believe there are six types at the moment but that list lives in the finance wiki so check there, and if the date range is big it chops it into pieces so the replica doesnt get blocked, and then it writes a csv for each report type and range into the exports bucket under a temporary name and renames it at the end so analysts never open a half written file, and if a run fails it writes nothing and shouts in the finance engineering channel, and if you rerun with the same run id it just replaces the file which is nice, and all of this lives in terraform where we have export_key, exports_bucket, reporting_ro_db, reporting_sg, export_audit and export_job_policy, and the whole thing sits in the reporting private subnet i guess, though thats more of a platform thing, and finance analysts download the finished files from the bucket (TBD whether they should get a link in an email instead, finance prefers the bucket for now).

for the security side the platform team gave me a list so im just going to paste what applies and say it in my own words after. Administrative and back-office access requires multi-factor authentication. Internal users receive only the roles required for their job, and roles are defined per service. Administrative and debug endpoints are not reachable from the public internet. Access rights to production systems are reviewed at least quarterly. and for data it says Personally identifiable information is encrypted at rest with AES-256. and also Only approved cryptographic algorithms are used; MD5, SHA-1, DES, 3DES and ECB mode are prohibited. plus Secrets do not appear in source code, configuration files, specifications or infrastructure definitions. and on the network The database and the message brokers sit in private subnets and are not publicly reachable. The exports bucket blocks public access and is private by default. then logging, Authentication failures, privilege changes and access to sensitive data are logged. and for personal data Only the personal data needed for the purpose is collected and stored. Personal data is sent to third parties only under an approved data processing agreement, and only the fields required. and for exports specifically Data exports require authorization, are encrypted, and expire after a limited time. finally Database queries are parameterized, and concatenating user input into queries is prohibited.
